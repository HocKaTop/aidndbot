# Доработки Nocturna — 7 октября 2026

Этот файл фиксирует текущий рабочий код после [аудита 29 сентября](project-audit-2026-09-29.md). Аудит описывает прежнюю версию; его примеры не следует считать перечнем текущих дефектов.

Последующий [плейтест собственного сеттинга](playtest-custom-setting-2026-10-07.md) обнаружил два текущих приоритетных дефекта: запрос исправления плана не помещается в стандартный контекст уже в короткой игре, а получение и использование сюжетного предмета в обычной кампании может оставаться только в прозе. Успешный учебный маршрут ниже не подтверждает готовность произвольных сеттингов. В протоколе также зафиксированы расхождения местоположения NPC и сюжетных фактов.

## Реализовано

- Локации сохраняют ID, описание, факты и известные выходы. `REVISIT_SCENE` возвращает в существующее место; `MOVE_NPC` перемещает NPC. Старые комнаты загружают сохранённые сцены. Присутствие NPC в сервере и интерфейсе определяется по ID локации с совместимостью со старыми данными.
- Явная атака учитывает названную цель, условие и классовый приём. Отсутствующая цель не заменяется другим NPC. Вопросы о пути, осмотр и отрицания не разрешают перемещение сами по себе.
- Проверки повествования отклоняют ряд неподтверждённых заявлений о переходе, смерти, предмете, бое и исходе цели. Это дополнительная защита: смысл произвольного текста полностью не проверяется.
- Успех и провал цели собственной кампании требуют предложения и подтверждения владельца. Решение связано с ID показанного предложения; устаревшее подтверждение или отказ не затрагивает новое. Ошибочно закрытую цель можно вернуть в работу, пока кампания продолжается; опыт не выдаётся повторно.
- Контекст модели выделяет текущую сцену, активные цели и названные игроком места; описания удалённых сущностей сокращаются в копии состояния. Полное сохранённое состояние остаётся в БД.
- Попытки игроков сохраняются отдельно от результатов движка. Скрытые заметки плана передаются повествователю и объединяются с его заметками после подтверждённого хода.
- Противники получают профили `minor`, `standard`, `elite` с разными HP, AC, попаданием и уроном. Старые NPC сохраняют прежний профиль.
- Добавлены отступление по известному выходу, отдых один раз в каждой локации и помощь павшему союзнику собственным лечебным зельем. Возвращение после отдыха в другом месте не позволяет лечиться повторно в прежнем.
- Ошибка итогового описания сохраняет уже рассчитанную механику с серверным текстом. Повествование ограничено 45 секундами и заканчивается за пять секунд до общего дедлайна, оставляя время сохранить ход и подтверждение команды. Ollama принимает максимум два одновременных запроса; температура генерации — 0.2.
- В учебном «Последнем фонаре» одна цель. Явные просьбы передать камень, возвращение к мосту и установка используют правила серверных кнопок. Успешный мирный обмен выдаёт один предмет; повторная просьба сообщает, у кого он уже находится. Собственные кампании сохраняют свободное планирование ведущим.
- Интерфейс показывает все активные цели и краткую сцену рядом с вводом. Таймер боя обновляет отдельный компонент, записи журнала мемоизированы. Новые механики доступны в Mini App и текстовом чате.

## Дальнейшие задачи

Аудит не закрыт полностью. Для следующего этапа остаются:

- Сохраняемые условия и этапы произвольных квестов, связывающие цели с проверяемыми фактами мира.
- Объединение синонимов названий локаций и архивирование большого мира; лимиты количества NPC, квестов и предметов сохраняются.
- Короткие транзакции с проверкой версии состояния вместо удержания блокировки PostgreSQL во время ответов модели.
- Ограничение числа отрисованных записей длинного журнала, группировка механики и профилирование на физическом телефоне.
- Передача предметов между героями и пополнение функциональных лечебных предметов через действия ведущего.
- Постоянный набор нескольких живых альтернативных прохождений и измерение ошибок/задержек. Один успешный маршрут не доказывает качество всех ответов модели.

## Применение изменений

Образы приложения агентом не собирались. Для запуска нового кода владелец проекта должен пересобрать backend и frontend и пересоздать соответствующие контейнеры своей Compose-конфигурацией. PostgreSQL и установленная Ollama использовались для тестов; реальные кампании и Telegram-сообщения тестами не изменялись.

Тесты запускаются на уже существующем образе с текущими исходниками через bind mount, без сборки и скачивания:

```bash
docker compose -f docker-compose.yml -f compose.test.yml run --no-deps --rm --pull never \
  -v "$PWD/backend:/src" tests go test ./... -count=1
```

## Результаты проверки

- Полный `go test ./... -count=1` с PostgreSQL — успешно, включая сохранение текстового маршрута, повтор команд без двойной выдачи предмета и сохранение хода у границы таймаута.
- `go vet ./...` — успешно.
- Frontend: 30 тестов, проверка TypeScript и production-сборка — успешно.
- `git diff --check` — успешно.
- Живой `TestLiveAdventureJourney` с установленной `qwen3.5:9b` — успешно: семь ходов, мирный обмен, один огненный камень, возврат в исходную локацию по ID, расход предмета и подтверждённый движком финал. Прогон занял около 101 секунды.

В живом тесте характеристики харизмы и мудрости повышены, чтобы проверять последовательность решений модели при гарантированном успехе навыков. Провал переговоров проверяется отдельным тестом. Вступление, поиск пути и описание результатов делает настоящая модель; явные операции учебного сценария выполняет сервер. Проза иногда повторяется и опережает механику: успешный прогон подтверждает состояние и завершение маршрута, а не полное отсутствие смысловых ошибок ведущего. Проверка в Telegram на телефоне остаётся после пользовательской сборки.
