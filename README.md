# Nocturna

Учебная D&D-like RPG в Telegram Mini App: общие комнаты, персонажи, AI Game Master через локальную Ollama и игровые механики на Go.

## Что работает

- Telegram initData: HMAC/hash, время авторизации, серверная сессия на 12 часов; отдельной регистрации нет.
- Создание кампании, настройки владельца, приглашение по коду/ссылке, лобби, персонажи и готовность.
- Удаление кампании владельцем с подтверждением кода, очисткой её данных и отключением участников.
- WebSocket с авторизацией первым сообщением, переподключением, ping и обновлением участников.
- Старт и пауза кампании, свободные текстовые действия и структурированные ответы Ollama.
- Завершение кампании владельцем с подтверждением, предложение финала от AI-ведущего с объяснением и выбором игрока, автоматический финал при гибели отряда; итоги сохраняются.
- Серверные кубики, проверки характеристик, атаки, ответные атаки NPC, HP и лечебные зелья.
- Сцены, NPC, квесты, инвентарь и журнал событий в PostgreSQL.
- Закрытые заметки AI-ведущего о придуманных им сюжетных зацепках сохраняются между ходами и не выдаются игрокам через API комнаты.
- Полная история кампании в Mini App: загрузка ранних событий и восстановление пропущенных записей после отключения.
- Telegram-бот внутри backend: long polling, текстовая игра и кнопка Mini App при настроенном HTTPS.
- Мобильный React-интерфейс с экранами кампаний, лобби, игры, героя, инвентаря и журнала.

Это упрощённая RPG с тремя игровыми классами: воин, плут и маг получают разные стартовые характеристики и по два классовых действия. Живые герои получают опыт за победы и завершённые квесты; развитие ограничено уровнями 1–3. Расы пока описательные. Доступны отступление, отдых и помощь павшему союзнику лечебным зельем. Вход/выход игроков и настройки доступны до старта. Владелец остаётся в комнате. Для первого старта у каждого участника должен быть живой герой и подтверждённая готовность; можно играть одному. Кубики для атак и проверок сервер бросает сам; справочный `/roll` доступен в текстовом чате. Полные правила текущей версии: [docs/game-rules.md](docs/game-rules.md).

Для первого знакомства в Mini App нажми «Быстрое приключение»: кампания «Последний фонарь» уже содержит мир и завязку. Создайте героев, пригласите друзей и подтвердите готовность. После «Начать приключение» мастер сам создаст вступление, сцену и первую цель. В собственной кампании это видимая игрокам конечная задача короткой истории; ведущий постепенно открывает путь к ней, сохраняя свободу действий отряда. При ошибке комната останется в лобби для повторного старта. Примеры рядом с полем действия помогают начать и допускают редактирование перед отправкой.

После закрытия всех целей вне боя AI-ведущий может завершить пользовательскую кампанию отдельным проверяемым действием; владелец также может подвести итоги вручную. Мирный выход из боя поддерживается через проверку харизмы и изменение отношения противника. Обзор сквозного пути и границ проверки: [docs/flow-review.md](docs/flow-review.md).

### Краткие ответы мастера и выбор механики

Обычный ход — 1–2 коротких абзаца, обычно 2–6 предложений. Вступление — максимум 2–3 коротких абзаца; результат броска или проверки — обычно один; эпилог — максимум два. Мастер не должен повторять сцену, пересказывать действие игрока или решать за его героя.

В схеме Ollama и при разборе ответа действуют одинаковые лимиты `narrative`: 900 Unicode-символов, для вступления — 1400. Текст не обрезается. Превышение вызывает один запрос исправления полного JSON. Если повторная ошибка случилась до расчёта механики, ход откатывается; после расчёта сервер сохраняет результаты с коротким описанием. Бюджет токенов включает весь JSON с действиями и памятью.

Без механической проверки мастер возвращает `actions=[]`; проверка характеристики — `SKILL_CHECK`; отдельный случайный бросок — `DICE_ROLL`. У последнего `name` содержит только запись кубиков. Схема именно этого действия использует общий с Go-парсером regex: 1–20 кубиков, 2–1000 граней, модификатор от −100 до +100, с сохранением ранее допустимых ведущих нулей. Названия NPC, сцен и предметов этим regex не ограничиваются. При исправлении ошибочный бросок можно удалить или заменить проверкой, а не только переименовать.

## Архитектура

```text
Telegram → Mini App → nginx → Go (REST + WebSocket + Bot)
                                ├─ PostgreSQL
                                └─ Ollama на домашнем ПК
```

```text
backend/
  cmd/server/          запуск и graceful shutdown
  internal/auth/       Telegram-подпись и подписанные сессии
  internal/server/     HTTP, комнаты, runtime и очередь ходов
  internal/game/       кубики, проверки, бой, состояние и действия
  internal/ai/         AIProvider, prompt builder, Ollama JSON schema
  internal/bot/        Telegram long polling
  internal/store/      сгенерированный sqlc код
  migrations/          SQL и embedded runner миграций
  queries/             SQL-запросы для sqlc
frontend/
  src/                 React, TypeScript, Telegram SDK, WebSocket hook
  nginx.conf           один origin для /, /api и /ws
scripts/setup_env.py    подготовка локальных секретов
```

Один процесс Go и одна goroutine на активную комнату. Очередь ограничена 16 командами. Runtime без клиентов удаляется после 10 минут простоя. На команду отведено 150 секунд; сетевой запрос Ollama ограничен 120 секундами. Перезапуск очищает только соединения и очередь, завершённые ходы восстанавливаются из БД. Незавершённый ход откатывается. После разрыва связи Mini App проверяет подтверждение действия; повторная отправка выполняется вручную с прежним идентификатором и не дублирует уже сохранённый результат.

Mini App сохраняет текст и отправленное действие отдельно для каждой кампании и пользователя в localStorage. Черновик восстанавливается в том же браузере и по тому же адресу приложения; текст очищается только после подтверждения успешного выполнения. Интерфейс показывает отправку, очередь, выполнение, успех или ошибку. Пока результат неизвестен, можно проверить его автоматически или вручную повторить исходное действие. Если действие ещё не выполнено, но игровой ход уже изменился, сервер отклонит устаревшую команду: нужно отправить новое действие с учётом текущей ситуации.

`rooms.state` содержит версионируемый в будущих миграциях JSONB-снимок мира для атомарного восстановления. В той же транзакции обновляются таблицы персонажей, NPC, инвентаря, сцен, квестов, памяти и событий. Записи в комнате защищены блокировкой PostgreSQL `FOR UPDATE NOWAIT`, в том числе HTTP-запросы. Параллельный запрос в занятую комнату получает `ROOM_BUSY`, освобождая соединение БД для других комнат. Во время AI-хода блокировка удерживается до завершения планирования и повествования, включая ограниченные попытки исправления ответа. Это осознанное упрощение для одного домашнего backend; UI показывает имя игрока, чьё действие выполняется. Активность передаётся по WebSocket, включая снимок при переподключении; очередь боя и время начала текущего хода хранятся в БД.

Модель сначала предлагает до четырёх действий. Движок валидирует их, выполняет максимум одну атаку/проверку за ход, рассчитывает числовые результаты и даёт NPC ответить. Затем модель получает результаты для повествования. Её поле `memory` сохраняет ограниченное число частных сюжетных заметок после подтверждённого хода, но не меняет игровые факты без действия движка. При следующем ходе ведущий видит эти заметки; в ответах комнаты игрокам их нет. Ошибка планирования откатывает ход; ошибка финального описания оставляет результаты движка. Логи не содержат полных промптов и Telegram-токена.

Ошибочный план или некорректный JSON получает одну попытку исправления до выполнения механики. Для финального повествования тоже разрешена одна попытка исправить формат, пустой текст или запрещённые новые действия. Повтор описания использует уже рассчитанные результаты. На повествование отведено до 45 секунд, с запасом пяти секунд до общего таймаута для сохранения. Если описание не удалось, сервер сохраняет механику с коротким текстом по её результатам: кубики не перебрасываются и предметы повторно не расходуются. Ошибка планирования откатывает ход. Ошибки соединения, таймауты и перегрузка автоматически не повторяются.

Ollama получает `temperature=0.2`; одновременно выполняются не больше двух запросов. Поле задаётся через `options` API согласно [документации Ollama](https://docs.ollama.com/api/chat). Заметки планировщика передаются повествователю и сохраняются вместе с его новыми заметками после подтверждённого хода.

Игрок получает отдельные пояснения для недоступной модели/адреса, таймаута, перегрузки, отсутствия связи, отклонённого запроса и неверного формата. Классификация HTTP-ответов опирается на [описание ошибок Ollama](https://github.com/ollama/ollama/blob/main/docs/api/errors.mdx). Тело ответа с технической ошибкой не показывается игроку и не передаётся модели как инструкция исправления. Саму работающую модель и её нагрузку нужно проверять отдельно от тестов с имитацией Ollama.

Контекст: настройки, текущая сцена, персонажи, активные цели, краткие записи об удалённых NPC и местах, до 20 последних событий, попытки игроков и до 6000 символов памяти о подтверждённых изменениях движка. Каждый запрос задаёт Ollama окно `OLLAMA_CONTEXT_LENGTH` (по умолчанию 16384 токена) и бюджет ответа: 1024 токена для обычного плана, 1280 для вступления, 768 для описания результатов механики. Консервативная оценка по длине UTF-8 оставляет запас под протокол; сначала сокращаются старые события и память. Если критическая часть мира не помещается, ход отклоняется с подсказкой увеличить окно, без потери сохранённых данных. Память обновляется инкрементально; отдельного LLM-суммаризатора пока нет. Mini App читает полную историю страницами по 50 событий; прежний API /events возвращает последние 100 событий для совместимости. Новые события упорядочены по серверной последовательности, включая несколько событий одной транзакции. У исторических событий с одинаковым временем миграция сохраняет прежний порядок по UUID: восстановить их исходный порядок невозможно.

## Требования и быстрый запуск

Для контейнерного запуска: Docker + Compose, Ollama с `qwen3:8b`, Telegram-бот. Для локальной разработки: Go 1.26+, Node.js 24, npm, sqlc. Python 3 нужен только для скрипта настройки.

1. Создай `.env` по `.env.example`. Укажи `TELEGRAM_BOT_TOKEN` и `TELEGRAM_BOT_USERNAME` без `@`.
2. Подготовь оставшиеся параметры, сохранив уже введённые секреты:

   ```bash
   python3 scripts/setup_env.py
   ```

3. На машине с Ollama:

   ```bash
   ollama pull qwen3:8b
   ```

4. Из корня проекта:

   ```bash
   docker compose up -d --build
   docker compose ps
   ```

Открой http://localhost:8080. В обычном браузере показывается экран входа через Telegram; поддельного локального входа в приложении нет. Проверка доступности: http://localhost:8080/healthz.

Миграции применяются при запуске backend под advisory lock; повторный запуск безопасен. PostgreSQL хранится в Docker volume. `docker compose down` останавливает проект и сохраняет данные. Не добавляй `-v`, если хочешь сохранить кампании.

## Telegram и публичный HTTPS

Для текстовой игры достаточно `BOT_ENABLED=true`. HTTPS нужен только для кнопки Mini App; при локальном `APP_BASE_URL` бот отвечает обычным текстом.

### Игра прямо в чате

Установи `BOT_ENABLED=true` в `.env`, выполни `docker compose up -d backend` и отправь боту:

```text
/start
/create Ночная таверна
/ready
/play
Я открываю дверь таверны и осматриваюсь.
```

`/create` сразу создаёт кампанию и героя (человек-воин, 24 HP). До `/play` друзья могут присоединиться через `/join КОД`; им тоже создаётся герой. Каждому игроку нужно написать боту лично. Автор получает ответ на действие, а остальные участники, выбравшие эту комнату в чате, автоматически получают её события — в том числе ходы из Mini App. `/create`, `/join` и `/room КОД` выбирают кампанию для текстовой игры и уведомлений. `/mute` выключает уведомления, `/unmute` включает; `/history` и `/state` доступны в обоих случаях.

Команды: `/defend` — защищаться в бою; `/pass` — пропустить ход; `/retreat` — попытаться уйти через известный выход; `/aid Имя` — поднять союзника своим зельем; `/rest` — отдохнуть в безопасном месте; `/skip` — пропустить задержавшегося игрока после минуты (владелец); `/mute` и `/unmute` — уведомления; `/ready` и `/unready` — готовность; `/state` — сцена, отряд, HP и предметы; `/history` — последние 10 событий; `/roll d20` — справочный кубик; `/confirm КОД` и `/continue КОД` — подтвердить или отклонить предложенный исход цели с кодом из `/state`; `/reopen` — вернуть ошибочно закрытую или проваленную цель; `/use 1` — применить предмет; `/claim`, `/bridge` и `/install` — шаги «Последнего фонаря»; `/pause` и `/play` — пауза/продолжение для владельца; `/rooms` — список кампаний; `/room КОД` — выбор своей кампании. `/delete` — инструкция удаления выбранной кампании, `/delete КОД` — подтверждение владельца. Любое обычное сообщение во время игры становится действием персонажа. `/help` показывает подсказку.

Авторизация текстового режима берёт `message.from.id` из Telegram Bot API; публичного обхода проверки initData нет. Состояние и механика общие с Mini App. Выбранная в чате комната сохраняется в PostgreSQL. Сообщения одного пользователя выполняются по порядку в отдельной очереди до 16 сообщений. Обрабатываются до 128 активных чатов; незанятый обработчик освобождается через минуту. Ожидание Ollama не останавливает приём сообщений других пользователей. Одновременно выполнять действия одной комнаты нельзя; запрос в занятую комнату получает подсказку дождаться завершения хода. Сообщения, отправленные до запуска процесса, не исполняются повторно после рестарта — отправь команду снова после запуска.

Классовые умения в чате: `/power` и `/guard` для воина, `/precise` и `/evade` для плута, `/firebolt` и `/barrier` для мага. Для атакующего умения укажи имя NPC, если рядом несколько целей: `/firebolt Похититель`.


### Завершение приключения

Кнопка «Завершить приключение» доступна владельцу во время игры и на паузе. Введи код кампании для подтверждения; при желании добавь итог истории. В чате отправь `/finish`, затем `/finish КОД`. Для перерыва используй `/pause`: после завершения продолжить эту кампанию нельзя.

Финал сохраняет причину, дату и итог истории; экран показывает число ходов, выживших героев и состояния квестов. При гибели отряда завершение автоматическое. В «Последнем фонаре» сервер завершает кампанию после проверенной установки камня у моста. В собственной кампании ведущий может предложить завершить цель с объяснением; владелец подтверждает её или продолжает историю. Подтверждение последней выполненной цели сохраняет финал. Отдельная команда ручного завершения владельцем не присваивает победу, не меняет квесты и не расходует ход. Участники могут перечитать события и посмотреть героев, подписчики получают уведомление с итогами. `/state` тоже показывает итоги; новую историю начинают в отдельной кампании через `/create` или главный экран Mini App.

### Совместная игра и доставка событий

Инициатор боя совершает открывающее действие. Затем живые герои бросают `d20 + модификатор ловкости` и с первого полного раунда ходят по результату инициативы. После каждого действия или пропуска отвечает один противник; если врагов несколько, они чередуются. Погибшие герои исключаются из обхода очереди. Раунд, текущий герой, чередование врагов и время ожидания сохраняются при перезапуске. Ручной бросок кубика остаётся справочным и не передаёт ход.

При обрыве связи текущий ход сохраняется. Игрок может вернуться и продолжить; после минуты ожидания владелец может нажать «Пропустить ход» или отправить `/skip`. Пропуск допускает ответную атаку противника. На паузе пропуски запрещены, после продолжения игрок получает новую минуту.

События для Telegram попадают в `telegram_outbox` в одной транзакции с игровым ходом. Четыре обработчика с отдельным пулом соединений отправляют их по порядку для каждого получателя и повторяют временные ошибки с задержкой до пяти минут. После блокировки бота доставка пользователю отключается; восстановить её можно через `/unmute`. При смене выбранной комнаты, выходе или отключении уведомлений ожидающие сообщения прежней подписки отбрасываются. При неопределённом результате сетевого запроса или перезапуске после отправки возможен повтор сообщения; игровой ход повторно не выполняется.


### Удаление кампании

В Mini App открой комнату и нажми значок корзины возле её названия. Введи код комнаты в окне подтверждения. В текстовом режиме сначала выбери кампанию через `/room КОД`, затем отправь `/delete` и указанную команду подтверждения.

Удалять можно в любом статусе, только владельцу. Удаляются комната, участники, герои, предметы, NPC, квесты, сцены, история и память этой кампании; аккаунты пользователей и другие кампании сохраняются. Подключённые Mini App возвращаются к списку комнат. Если сейчас выполняется ход, удаление возвращает ошибку занятости: дождись ответа мастера и повтори. Отменить уже выполненное удаление нельзя.

### Временный адрес без настройки домена

Запуск приложения и настройка туннеля одной командой (после заполнения `.env`):

```bash
make tunnel
```

Команда соберёт и запустит сервисы, дождётся адреса Cloudflare, запишет его в `.env`, включит бота, настроит кнопку «Открыть игру» в Telegram и применит настройки backend. Если адрес изменился, снова выполни `make tunnel`. URL Main Mini App в BotFather, если он настроен, нужно обновить вручную.

Логи туннеля: `make tunnel-logs`. Остановить туннель: `make tunnel-down`.

Те же действия вручную:

```bash
docker compose -f docker-compose.yml -f compose.tunnel.yml up -d tunnel
docker compose -f docker-compose.yml -f compose.tunnel.yml logs tunnel
```

В логах появится `https://…trycloudflare.com`. Это публичный адрес приложения; он может измениться после пересоздания туннеля. Укажи его в `.env`:

```dotenv
APP_BASE_URL=https://YOUR-ADDRESS.trycloudflare.com
BOT_ENABLED=true
```

Настроить адрес и кнопку меню бота автоматически можно командой (подставь выданный URL):

```bash
python3 scripts/configure_telegram.py https://YOUR-ADDRESS.trycloudflare.com
docker compose up -d backend
```

Скрипт устанавливает кнопку «Открыть игру» через Telegram API, проверяет её и обновляет `APP_BASE_URL` в `.env`, сохраняя секреты. Чтобы открыть Mini App через меню чата или кнопку после `/start`, настройка Main Mini App в BotFather не обязательна. Для кнопки в профиле и invite-ссылок `?startapp=...` настрой Main Mini App ниже. После изменения временного адреса повтори команду и обнови URL в BotFather, если он уже указан там.

В **@BotFather → /mybots → твой бот → Bot Settings → Configure Mini App** включи Main Mini App и задай тот же HTTPS URL. Затем отправь своему боту `/start` и нажми «Открыть Nocturna».

Для Main Mini App `TELEGRAM_APP_NAME` оставь пустым. Приглашение выглядит так:

```text
https://t.me/BOT_USERNAME?startapp=ROOM_CODE
```

Если создал именованное приложение через `/newapp`, укажи его short name в `TELEGRAM_APP_NAME`. Тогда ссылка будет `https://t.me/BOT_USERNAME/APP_NAME?startapp=ROOM_CODE`.

Открыв приглашение, игрок увидит заполненный код и сам подтвердит вход. После создания героев все участники подтверждают готовность, затем владелец запускает игру. Мастер автоматически создаёт вступление, начальную сцену и первую цель.

### Собственный домен

Регистратор домена может остаться прежним. Добавь домен в Cloudflare, проверь DNS-записи и замени nameservers у регистратора на выданные Cloudflare. После активации создай постоянный Cloudflare Tunnel и маршрут для нужного поддомена на `http://localhost:8080`, если cloudflared запущен на ПК, либо `http://frontend:80`, если он в сети Compose. Обнови `APP_BASE_URL` и URL в BotFather. PostgreSQL и Ollama в туннель не добавляются.

Документация: [Telegram Mini Apps](https://core.telegram.org/bots/webapps), [Cloudflare Quick Tunnels](https://developers.cloudflare.com/cloudflare-one/networks/connectors/cloudflare-tunnel/do-more-with-tunnels/trycloudflare/).

## Ollama в Windows и backend в Docker

По умолчанию используется `OLLAMA_URL=http://host.docker.internal:11434`. Проверка из контейнера:

```bash
docker compose exec backend wget -T 8 -qO- http://host.docker.internal:11434/api/tags
```

В списке должна быть `qwen3:8b`. Если запрос проходит, менять сетевые настройки Ollama не нужно. Если нет, проверь, запущена ли Ollama, доступ Docker Desktop к Windows и правила firewall; настройка адреса прослушивания описана в [Ollama FAQ](https://docs.ollama.com/faq). Не направляй Cloudflare Tunnel на порт 11434.

## Переменные окружения

| Имя | Назначение |
|---|---|
| `TELEGRAM_BOT_TOKEN` | Токен BotFather |
| `TELEGRAM_BOT_USERNAME` | Username без `@`, нужен для ссылок |
| `TELEGRAM_APP_NAME` | Short name именованного Mini App; для Main Mini App пусто |
| `APP_BASE_URL` | Единый origin приложения; публичный HTTPS для кнопки Mini App |
| `BOT_ENABLED` | `true` включает long polling, по умолчанию `false` |
| `POSTGRES_PASSWORD` | Пароль БД в Compose, генерируется скриптом |
| `JWT_SECRET` | Ключ HMAC внутренней сессии, минимум 32 символа; сессия не JWT |
| `OLLAMA_URL` | Адрес Ollama, доступный backend |
| `OLLAMA_CONTEXT_LENGTH` | Окно модели, по умолчанию 16384 токена, допустимо 8192–32768; увеличение требует больше памяти |
| `DEFAULT_OLLAMA_MODEL` | По умолчанию `qwen3:8b`; можно выбрать в настройках комнаты |
| `APP_PORT` | Локальный порт nginx, по умолчанию 8080 |
| `DATABASE_URL` | Для запуска Go вне Compose; внутри формируется автоматически |
| `HTTP_ADDR` | Адрес Go-сервера, по умолчанию `:8081` |

Для совместимости `TELEGRAM_WEBAPP_URL` читается backend как запасной вариант при отсутствии `APP_BASE_URL`. Compose использует `APP_BASE_URL`. `.env` не попадает в Git и Docker build context.

## Проверки

```bash
cd backend
go test ./...
go vet ./...
cd ../frontend
npm run test
npm run typecheck
npm run build
cd ..
docker compose -f docker-compose.yml -f compose.test.yml run --build --rm tests
```

Unit-тесты проверяют подпись и возраст initData, сессии, парсер и границы кубиков, бой, права комнаты, валидацию действий и ошибки Ollama. Интеграционный тест создаёт отдельную временную схему, использует тестовый bot token и проверяет два WebSocket-клиента, лимиты, права, персонажей, готовность, старт, сохранение, откат при недоступной AI и чтение состояния новым экземпляром сервера. Дополнительные сценарии проверяют удаление с двумя реальными WebSocket-соединениями, права и подтверждение, занятую комнату, каскадную очистку и текстовую команду. Проверяются порядок событий, сохранение результатов при ошибке повествования, последствия проверки навыка и расход хода на зелье. Тестовая схема удаляется; реальные кампании не затрагиваются.

Завершение кампаний проверяется на права владельца, подтверждение, сохранение итогов и уведомлений, защиту от повторов, отклонение дальнейших действий и чтение старых финалов.

`TestAdventureFromCreationToCompletedGoalAndFinale` проходит создание комнаты, вход второго игрока, героев, готовность, старт, получение и расход сюжетного предмета, предложение завершить цель и подтверждённый финал через HTTP и два WebSocket-соединения. Мастер в этом тесте запрограммирован; качество настоящей модели проверяется отдельно.

Отдельные интеграционные сценарии проверяют подтверждение после перезапуска, повтор без дублирования событий и уведомлений, однократный расход предмета и бросок кубиков, откат ошибки, отклонение устаревшего хода и переподключение WebSocket во время выполнения.

История проверяется на более чем 200 событиях с одинаковым временем, параллельное добавление новых ходов, отсутствие пропусков и повторов, права доступа и точность больших курсоров. Frontend-тесты дополнительно проверяют догрузку нескольких страниц после отключения, совмещение старых и новых записей, смену комнаты, повтор после ошибки и сохранение позиции чтения.

Frontend-тесты в Vitest/jsdom проверяют подтверждение удаления, права, ошибку занятой комнаты, возврат к списку, игнорирование запоздалых ответов и остановку переподключений после удаления. Проверяются сохранение черновиков по комнатам и пользователям, двойное нажатие, восстановление подтверждения, повтор с прежним ID и отсутствие автоматического выполнения после переподключения. Это автоматическая проверка интерфейса, не визуальная проверка внутри Telegram.

Опциональная проверка настоящей модели:

```bash
docker compose -f docker-compose.yml -f compose.test.yml run --build --rm \
  -e OLLAMA_SMOKE_URL=http://host.docker.internal:11434 \
```

Этот тест использует вымышленную кампанию в памяти, без Telegram и сохранения в БД. Он проверяет вступление, последовательность мирных действий и завершение исходного квеста. Генерация и кубики недетерминированы: провал требует чтения журнала, а не автоматического повтора до зелёного результата. Для Ollama на хосте замени URL на доступный контейнеру адрес.

## Протокол и API

После `POST /api/auth/telegram` с `{ "initData": "raw Telegram initData" }` frontend держит подписанный токен только в памяти и отправляет `Authorization: Bearer TOKEN`. Срок жизни исходного initData — один час, допускается 30 секунд рассинхронизации времени.

WebSocket: `/ws/rooms/{id}`. Первое сообщение за 10 секунд:

```json
{"type":"auth","data":{"token":"SESSION_TOKEN"}}
```

Команды (для каждого нового действия создаётся новый UUID; при повторной отправке весь пакет сохраняется):

```json
{"id":"UUID","type":"ready","data":{"ready":true}}
{"id":"UUID","type":"start_game","data":{}}
{"id":"UUID","type":"player_action","expectedTurn":3,"data":{"text":"Я атакую гоблина мечом"}}
{"id":"UUID","type":"roll_dice","data":{"notation":"2d6+3"}}
{"id":"UUID","type":"use_item","expectedTurn":3,"data":{"itemId":"UUID"}}
{"id":"UUID","type":"pass_turn","expectedTurn":3,"data":{}}
{"id":"UUID","type":"skip_turn","expectedTurn":3,"data":{"turn":3}}
{"id":"UUID","type":"finish_game","expectedTurn":3,"data":{"code":"КОД_КОМНАТЫ","text":"Итог истории (необязательно)"}}
```

`expectedTurn` — номер `state.turn` из последнего снимка; Mini App передаёт его для действий, предметов, пропуска хода и завершения кампании. Успешное подтверждение хранится в `command_receipts` в одной транзакции с игровыми изменениями и уведомлениями. Повтор того же пакета после перезапуска возвращает успех без повторного выполнения; другой пакет с уже использованным ID отклоняется. ID привязан к комнате и пользователю. Старые клиенты без `id` поддерживаются, но защиты от повторного выполнения у них нет.

Проверка результата без выполнения действия:

```json
{"type":"command_status","id":"UUID"}
```

Ответ и обновления выполнения: `{"type":"command_status","data":{"id":"UUID","status":"completed"}}`. Статусы: `queued`, `processing`, `completed`, `failed`, `unknown`; пояснение — необязательное `data.message`. `failed` означает отклонённую команду, `unknown` — отсутствие достоверного подтверждения; при нём повторяют исходный пакет с тем же ID. После переподключения клиент запрашивает статус, но не выполняет действие автоматически. Неуспешные команды откатываются и не сохраняют подтверждение в БД.

События `room_state`, `player_joined`, `player_left`, `character_updated`, `game_status_changed` сигнализируют о необходимости загрузить свежий snapshot через REST: `data.refresh=true`. `room_activity` передаёт `data.processing` и имя действующего игрока `data.name`, включая снимок активности при подключении. `error` содержит `data.message`. Терминальные события `room_deleted` и `room_left` возвращают клиента к списку комнат и закрывают WebSocket без повторного подключения. Детали механики хранятся в typed payload журнала.

REST: `/api/me`, `/api/rooms` (GET/POST), `/api/rooms/join` (POST по коду), `/api/rooms/{id}` (GET/PATCH/DELETE), `/{id}/join`, `/leave`, `/start`, `/pause` (POST), `/characters` (POST), `/characters/me`, `/members`, `/quests`, `/events` (GET). `PATCH /api/characters/{id}` позволяет владельцу персонажа изменить имя, расу и класс до старта; числовые характеристики не принимаются от клиента.

`DELETE /api/rooms/{id}` принимает `{ "code": "КОД_КОМНАТЫ" }`. Ответ — `{ "deleted": true }`; отсутствие прав — 403, неправильный код — 400, выполняющийся ход — 409 `ROOM_BUSY`, удалённая комната — 404.

### Страницы истории

`GET /api/rooms/{id}/events/page` возвращает последние 50 событий. `limit` задаёт размер страницы от 1 до 100. Для чтения прошлых событий передавай `before=CURSOR`; для восстановления пропущенных новых — `after=SEQUENCE` последнего полученного события. `after=0` начинает чтение с начала; одновременно указывать `before` и `after` нельзя.

```json
{"events":[{"id":"UUID","sequence":"123","type":"GM_MESSAGE","createdAt":"2026-09-17T12:00:00Z","payload":{"text":"Вы подошли к мосту."}}],"nextCursor":"123"}
```

Каждая страница упорядочена от старых событий к новым. `nextCursor` — курсор продолжения в выбранном направлении или `null`, если дальше записей нет. На первом запросе без направления продолжение идёт в прошлое через `before`. Номера последовательности и курсоры передаются строками, чтобы JavaScript не округлял большие значения. Чтение доступно только участникам комнаты, включая завершённые кампании.

Mini App сохраняет загруженные страницы при обновлении и догружает новые через `after`, пока не получит все пропущенные события. Чтение старых записей не сбрасывается к последнему сообщению. Старый `/events` остаётся совместимым и возвращает массив из последних 100 событий; `/history` в чате показывает последние 10.
